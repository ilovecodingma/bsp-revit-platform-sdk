# 흐름 설계 — 한 줄에서 «매일 자동» 까지

> 두 개의 흐름만 있다. **A. 도입 (한 번)** 과 **B. 상시 (매일 저절로)**.
> 각 칸은 누가 하는지, 실패하면 어디로 가는지가 정해져 있다. 사람이 판단할 자리는 딱 두 곳이다.

---

## A. 도입 흐름 — 한 번, 사람 개입 0~1회

```
 사람          AI(클로드)                       스크립트/코어                    결과
 ────          ──────────                       ───────────────                 ────
 한 줄  ──▶  ① SDK 내려받기                    git clone / zip
   │           └ CLAUDE.md → AI\RUN.md 읽음
   │
   │         ② 탐지  ───────────────────▶  wizard.ps1 -Auto
   │              · 리빗 연도   (설치 폴더에서)
   │              · 애드인 프로젝트 (IExternalApplication 검색)
   │              · 애드온 폴더  (Addins\<연도>\*)
   │              · 리빗 켜짐?  → 켜져 있으면 «설치» 칸만 건너뜀
   │
   ├◀── 질문 1개 (서버 주소) ── 모르면 묻지 않고 오프라인으로 진행
   │
   │         ③ 적용  ───────────────────▶  apply.ps1
   │              보관(snapshot) → 두 줄 삽입 → 참조 추가
   │              → config.json 기록 → (꺼져 있으면) 애드온 폴더에 배치 → 빌드
   │
   │         ④ 검증  ───────────────────▶  bsp-probe cycle · selftest
   │              6~7줄 PASS/FAIL 로 판정 (사람 눈 안 씀)
   │                    │
   │                    ├─ 전부 PASS ───────────────────────────▶ ⑥ 보고 3줄
   │                    │
   │                    └─ FAIL ─▶ ⑤ 수선 (RUN.md 2장 표) ─▶ ④ 로 1회만 복귀
   │                                 예) 계약 DLL 옛 연도 → 재빌드
   │                                     진입점 특이 → 두 줄 직접 삽입
   │                                 같은 줄 2회 FAIL 이면 사람에게
   │
   ◀── ⑥ 보고 : 적용 / 서버 / 다음 한 줄  (되돌리기 = snapshot -Restore)
```

**사람이 판단하는 두 곳**
1. 서버 주소를 줄 것인가 (안 줘도 진행됨 — 나중에 `config.json` 한 줄)
2. 리빗을 언제 껐다 켤 것인가 (AI 는 리빗을 임의로 끄지 않는다)

## B. 상시 흐름 — 매일, 사람 개입 0

```
  리빗 켜짐
      │
      ├─ 애드온 OnStartup ─▶ BspAgent.Attach()
      │        · 세션 표시   revit\<pid>.json  (pid + 시작시각)
      │        · 매니저 없으면 점화 (별도 프로세스 · Job 탈출 · 핸들 차단)
      │        · 곧바로 리턴 — 리빗 기동을 붙잡지 않는다
      │
      ▼
  매니저 (밖)                                 리빗 (안)
  ─────────────                               ───────────
  ① 카탈로그 확인 ─ 서버 ─▶ 바뀐 것만 받기      도구 실행마다 한 줄 기록
  ② SHA-256 검증 ─ 틀리면 배치 거부            (runlog.jsonl)
  ③ 안 잠긴 것은 지금 배치                      멈춤·크래시는 .running 으로
  ④ 잠긴 것은 큐로                               «범인» 이 남는다
  ⑤ 2초마다 요청 확인 (cmd\)  ◀── 리빗 안 «받기» 버튼
  ⑥ 60초마다 메모리·모듈 스냅샷
      │
  리빗 꺼짐 (= 마지막 세션 사라짐)
      │
      ├─ 큐 적용 (잠겼던 파일 교체)
      ├─ 기록 업로드 (서버 있으면)
      └─ 매니저 스스로 종료 ─▶ PC 에 상주물 0
      │
  다음에 리빗 켜면 ▶ 최신 상태로 시작
```

### 왜 이 순서인가 (바꾸면 깨지는 것)

| 칸 | 이유 |
|---|---|
| 점화가 «먼저» | 세션 표시가 있어야 매니저가 자기 수명을 안다 |
| 받기가 «켜질 때» | 껐을 때 받으면 껐다 바로 켤 때 아직 안 받아져 있다 |
| 교체가 «꺼질 때» | 리빗이 쥔 DLL 은 리빗 자신도 못 바꾼다 |
| 검증이 «교체 전» | 순서를 바꾸면 실패했을 때 아무것도 없는 PC 가 남는다 |
| 종료가 «세션 기준» | 프로세스 이름으로 세면 우리 애드온이 없는 리빗까지 센다 |

### 여기서 «동적 로드» 가 끼는 자리

```
도구 첫 클릭 ─▶ BspAgent.Stage("제품") ─▶ 세션 복사본에서 Assembly.LoadFrom
                     │
                     └ 원본은 아무도 안 잡는다 ─▶ 매니저가 켜진 채로 새 버전을 덮어씀
                                                  (반영은 다음 기동, 대기 큐가 안 쌓인다)
```

## C. 상태 — 매니저가 가질 수 있는 네 가지

```
   (없음) ──점화──▶ [준비]
                      │  초기 동기화 (받아 두기)
                      ▼
                   [감시]  ◀── 요청 2초 / 스냅샷 60초
                      │
        마지막 세션 사라짐 │
                      ▼
                   [정리]  큐 적용 · 기록 업로드
                      │
                      ▼
                   (없음)      ← 유예 60초 안에 리빗이 다시 뜨면 [감시] 로 복귀
```

- 한 대에 **하나만** ([감시] 상태는 뮤텍스가 지킨다. 두 번째는 즉시 물러남)
- 리빗이 크래시해도 [정리] 를 거친다 (세션 파일은 pid + 시작시각으로 걸러짐)
- 서버가 없어도 [감시] 는 돈다 (업데이트만 쉬고 기록·수명 관리는 계속)

---

## D. 실패했을 때 어디로 가나

| 어디서 | 어떻게 되는가 | 사용자가 겪는 것 |
|---|---|---|
| 서버 안 보임 | 마지막 상태로 계속 | 아무 일도 없음 |
| 해시 불일치 | 배치 거부, 기존 설치 유지 | 아무 일도 없음 (기록에만 남음) |
| 파일 잠김 | 큐 → 다음 종료 때 | «다음 기동에 적용» 이라고 화면이 말함 |
| 기록 전송 실패 | 오프셋 유지, 다음에 다시 | 아무 일도 없음 |
| 도구가 죽음 | 깔때기가 잡아 기록 + 창 | 무엇이 어디서 죽었는지 보임 |
| 매니저가 못 뜸 | 애드온은 정상 동작 | 업데이트만 멈춤 (`agent.err.log` 에 이유) |

**원칙 하나** : 어느 칸이 실패해도 **도면 작업은 멈추지 않는다.**

---

## E. 이 흐름이 성립하려면 필요한 것

| 필요 | 상태 |
|---|---|
| 애드인에 두 줄 | `wizard.ps1` 이 자동 삽입 |
| 매니저·에이전트 배치 | 자동 (애드온 옆) |
| 서버 목록 한 장 | 주소만 있으면 됨 (`SPEC\ADAPTER.md` 세 길) |
| 코드 서명 | **아직 미정** — 무인 배포의 전제. 이것만 사람이 정해야 한다 |
