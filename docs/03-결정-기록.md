# 결정 기록 — 무엇을 왜 그렇게 정했나

> 코드는 «어떻게» 만 말한다. 이 문서는 «왜» 를 남긴다.
> 되짚을 일이 생기면 여기부터 본다. 뒤집힌 결정도 지우지 않고 «뒤집힘» 으로 남긴다.

---

## 1. 우리가 만드는 것은 «가장 아래 한 겹» 뿐이다

| | |
|---|---|
| **정한 것** | 코어(붙이기·받기·검증·배치·수명·기록) + 하네스만 만든다. 서버·화면·심사·요금은 만들지 않는다 |
| **왜** | 상대는 이미 리빗 플랫폼을 갖고 있다. 우리가 서버를 만들면 **플랫폼이 두 개**가 된다 |
| **결과** | `BSP.Platform.Agent.dll`(리빗 참조 없음) + `bsp-launcher.exe` + 하네스 다섯 |

## 2. 리빗 안이 아니라 «별도 프로세스» 에서 관리한다

| | |
|---|---|
| **정한 것** | 애드온은 점화만 하고, 관리는 밖에서 도는 프로세스가 한다 |
| **왜** | .NET Framework 는 어셈블리를 내릴 수 없고, 리빗이 켜진 동안 DLL 은 잠긴다.<br>리빗 안에 관리를 두면 «리빗이 살아 있는 동안만» 관리된다 |
| **실측** | Job(kill-on-close) 안에서 탈출이 거부된 채 그냥 띄웠더니 부모와 함께 사망 → `IsProcessInJob` 확인 후 WMI 우회로 해결 |

## 3. 수명은 «애드온» 을 따라간다 (뒤집힌 결정)

| | |
|---|---|
| **처음** | 매니저는 상주 — 로그온 때 떠서 계속 돈다 |
| **뒤집음** | «리빗과 무관하지만 리빗이 꺼지면 꺼져야지» (사용자) |
| **지금** | 애드온 세션(`revit\<pid>.json`)이 하나도 없으면 마무리하고 **스스로 종료** |
| **왜 프로세스 이름이 아니라 세션인가** | 애드온이 안 뜬 리빗은 우리와 무관하다. 크래시로 `OnShutdown` 을 못 불러도 **pid + 시작 시각**으로 죽은 세션을 걸러낸다 |
| **결과** | 리빗을 안 쓰는 날에는 PC 에 아무것도 돌지 않는다 |

## 4. 업데이트는 «받고 · 검증하고 · 그 다음에 교체»

| | |
|---|---|
| **사고** | 옛 버전을 먼저 지우고 새 버전을 받다가 해시가 틀려 **둘 다 사라짐** |
| **고침** | 필요한 파일을 전부 받아 전부 검증한 뒤에야 교체를 시작한다. 하나라도 어긋나면 기존 설치를 그대로 둔다 |
| **부수 사고 2** | .NET 기본 HTTP 캐시 때문에 **서버에 새 카탈로그를 올려도 옛 목록을 계속 읽었다** → 캐시 금지 |
| **부수 사고 3** | 리빗이 물고 있는 파일의 해시를 읽다 예외 → 그 제품 동기화 전체 사망 → 읽기 실패는 «다르다» 로 처리 |

## 5. 리빗 «안에서» 받는 경험은 유지한다

| | |
|---|---|
| **요구** | 대표는 리빗 안에서 목록 보고 눌러 받기를 원한다 |
| **제약** | 이미 로드된 DLL 은 리빗 자신도 못 바꾼다 |
| **타협** | 누르는 것은 안에서(`Install()`), 바꾸는 것은 밖에서. 새 도구는 즉시, 쓰이는 중인 것은 «다음 기동에 적용» 이라고 **정확히 말한다** |
| **실측** | 요청 → 받기 → SHA-256 검증 → 배치 왕복 **1.3초** |

## 6. 서버는 «남의 것» 이라고 전제한다

| | |
|---|---|
| **정한 것** | 런처는 서버 스키마를 전제하지 않는다. 주소·인증 헤더·정책은 전부 설정값 |
| **필요한 것** | **목록 한 장(JSON) + 그 목록이 가리키는 파일**. 그 둘뿐 |
| **못 고치는 서버는** | 목록을 만들어 같이 올리거나(`make-catalog.ps1`), 변환기를 하나 둔다. **런처는 고치지 않는다** |
| **덤** | `file:` 도 되므로 사내 공유 폴더만으로도 배포가 성립한다 |

## 7. 회원·심사·요금은 서버의 일이다

| | |
|---|---|
| **정한 것** | 런처의 회원 확인은 기본 **끔**. 카탈로그에 있는 것은 서버가 이미 걸러 준 것으로 본다 |
| **왜** | 누구에게 무엇을 줄지는 사업 판단이다. 클라이언트에 정책을 박으면 정책을 바꿀 때마다 배포해야 한다 |
| **남긴 것** | `requireMember: true` 로 켜면 fail-closed 로 동작한다 |

## 8. 사람 눈을 판정에서 뺀다 (하네스)

| | |
|---|---|
| **정한 것** | «돌아가는 것 같다» 를 없애고 PASS/FAIL·종료 코드로 바꾼다 |
| **도구** | `bsp-probe cycle`(7줄) · `selftest.ps1`(5~7줄) · `healthcheck.ps1` · `make-catalog.ps1` · `snapshot.ps1` |
| **왜** | 그래야 상대가 **우리 없이** 진도를 뺄 수 있다. 그게 이 SDK 의 목적이다 |

## 9. 이번 범위에서 뺀 것

| 뺀 것 | 이유 | 다시 볼 조건 |
|---|---|---|
| AI · MCP 연계 | 규격이 파일·HTTP 두 갈래뿐이라 나중에 붙여도 구조가 안 바뀐다 | 코어가 현장에 자리잡은 뒤 |
| 라이선스 서버 | 회원 확인 하나로 갈음 | 외부 판매가 생길 때 |
| 실기 러너 자동화 | 정적 검사는 돈다. 연도별 리빗 실행 검사는 수동 | 연도가 셋 이상 될 때 |
| 런처 자기 자신의 자동 업데이트 | 실패하면 복구 수단이 없다 | 서명·롤백이 갖춰진 뒤 |

## 10. 아직 정해지지 않은 것 — **코드 서명**

이 SDK 가 대신해 줄 수 없는 유일한 항목이다.

- 서명이 없으면 리빗이 «보안» 대화상자를 띄우고 **답할 때까지 기동이 멈춘다** (실측 1시간 45분)
- 무인·전사 배포가 성립하지 않는다
- 정할 것 : **누구 이름으로 서명하는가** (회사 하나 / 공급사별), 키는 어디에 두는가

이 결정이 심사 정책의 출발점이다. 나머지는 전부 그 뒤에 온다.
