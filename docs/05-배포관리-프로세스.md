# 마켓스토어 배포 관리 프로세스

> 화면(스토어 UI)은 HTS 것을 그대로 쓴다. 이 문서는 **그 뒤에서 도는 절차**다 —
> 무엇을 올리고, 무엇을 막고, 어떻게 되돌리는가.
>
> 원칙 : **모든 관문은 기계가 먼저 본다.** 사람은 기계가 통과시킨 것만 판단한다.

---

## 1. 한 장 흐름

```
 만든 사람                 관문(기계)                사람            현장
 ─────────                ──────────                ────            ────
 빌드 ──▶ 올리기 ──▶ ① 정적 검사 ──FAIL──▶ 반려(이유 그대로)
                         │PASS
                         ▼
                      ② 실기 검사 (연도별)──FAIL──▶ 반려
                         │PASS
                         ▼
                      ③ 판정 기록 ──────────▶ 승인/보류 ──▶ ④ 게시
                                                              │
                                              ⑤ 단계적 확산 ◀─┘
                                              (1대 → 5대 → 전체)
                                                    │
                                              ⑥ 관찰(기록·사고)
                                                    │
                                    이상 ──▶ ⑦ 되돌리기 / 차단
```

---

## 2. 관문 ① 정적 검사 — `bsp-verify.exe` (초 단위, 리빗 없이)

| 항목 | 기준 | 안 지키면 |
|---|---|---|
| 참조 API 일치 | 모든 `RevitAPI*` major == 선언 연도 − 2000 | 버튼 누르는 순간 사망 |
| 런타임 계열 | ≤2024 net48 / 2025+ net8 | 아예 로드 안 됨 |
| 코드 서명 | 전부 서명 · 발급자 허용 목록 | 기동 정지 (실측 1h45m) |
| 동봉 금지 | `BSP.Contracts` · `RevitAPI*` · `AdWindows` 없을 것 | 계약 분열 |
| 내부 버전 충돌 | 같은 어셈블리 두 버전 없을 것 | `Assembly version conflict` 로 로드 거부 |

**FAIL 이면 업로드가 거기서 멈춘다.** (`publish.ps1` 이 그렇게 되어 있다)

## 3. 관문 ② 실기 검사 — 격리 리빗, 연도별

| 항목 | 예산/기준 |
|---|---|
| 로드 여부 | 저널에 `Starting External Application` |
| 기동 추가 시간 | **200ms 미만** |
| 정적 초기화 강제 실행 | 모든 타입 cctor — «누르면 죽을 코드» 를 미리 잡는다 |
| 리본 생성 | 버튼 수 · **자기 탭을 만들지 않았는가** |
| 자원 증가 | 메모리·스레드·핸들·모듈 |

> cctor 강제 실행은 파일·네트워크를 건드릴 수 있다. **격리 머신에서만** 돌린다.

## 4. 관문 ③ 판정 기록

- 기계 결과는 `POST /api/verdict` 로 쌓인다 (제품 × 버전 × 연도)
- `fail` 이 하나라도 있으면 **승인 버튼이 잠긴다.** 이미 승인된 것도 `pending` 으로 되돌아간다
- 사람의 승인은 `POST /api/review` (대표만)

**사람이 보는 것** : 무엇을 하는 도구인가 · 권한이 과하지 않은가 · 설명이 사실인가.
**사람이 안 보는 것** : 버전·서명·충돌 — 기계가 이미 봤다.

---

## 5. 게시와 확산

| 단계 | 대상 | 넘어가는 조건 |
|---|---|---|
| 내부 1대 | 만든 사람 PC | 실기 6줄 통과 |
| 시범 5대 | 지정 사용자 | 24시간 사고 0 · 기록에 실행 흔적 |
| 전체 | 전 PC | 시범에서 반려 없음 |

확산은 **카탈로그의 `latest` 를 올리는 것**으로 끝난다. 각 PC 는 리빗을 껐다 켜면 최신이 된다.
단계는 회원(`allow`)으로 가른다 — 시범 대상만 새 버전을 보게 한다.

---

## 6. 되돌리기와 차단

| 상황 | 조치 | 걸리는 시간 |
|---|---|---|
| 새 버전이 나쁘다 | 카탈로그 `latest` 를 옛 버전으로 | 다음 기동 |
| 특정 제품을 급히 끈다 | 회원 `allow` 에서 뺀다 | 다음 기동 |
| 그 PC 만 끈다 | `bsp-launcher disable <제품>` | 즉시 |
| 계속 죽인다 | **자동 격리 3회 규칙** | 세 번째 사고 직후 |

> **옛 버전을 카탈로그에서 지우지 않는다.** 지우면 되돌릴 방법이 없어진다.
> `make-catalog.ps1 -Merge` 가 옛 버전을 남기도록 만들어져 있다.

---

## 7. 누가 무엇을 하나

| 역할 | 할 수 있는 것 |
|---|---|
| 개발자 | 올리기 · 검사 결과 제출 · 자기 제품 기록 |
| 타사 | 자기 제품만 (남의 것은 보이지도 않음) |
| 대표 | 승인·반려 · 회원·번들 · 차단 · 롤백 · 전체 기록 |
| 제도사 | 받아 쓰기 · 버그 리포트 |
| 매니저(기계) | 받기·검증·배치·격리 — **사람 손 없이** |

---

## 8. 이 프로세스가 성립하려면 필요한 것

| 필요 | 상태 |
|---|---|
| 정적 검사 | **있음** |
| 판정·승인 저장 | 참조 서버에 있음 (운영 서버에 옮기면 됨) |
| 단계적 확산 | 회원 기능으로 가능 |
| 되돌리기 | 카탈로그에 옛 버전만 남기면 됨 |
| 자동 격리 | **있음** (3회) |
| **코드 서명** | **없음 — 이것만 정해지면 무인 배포가 성립한다** |
