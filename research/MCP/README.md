>

## 1. 무엇을 알아보려는 것인가

한 문장 : **리빗 안의 일을 AI 가 «보고 · 시키게» 하되, 도면을 안 흘리고 안 망가뜨리는 방법.**

| 갈래 | 질문 |
|---|---|
| A. 읽기 | 모델·뷰·선택을 AI 가 어떻게 보나. 무엇까지 보여도 되나 |
| B. 시키기 | AI 가 도구를 부르게 할 것인가. 부른다면 누구 이름으로, 어디까지 |
| C. 운영 | 기록(`runlog`)·사고 데이터를 AI 가 읽고 «무엇이 문제인가» 를 말하게 |
| D. 개발 | 애드인 만들 때 규격·계약을 AI 가 지키게 (이미 `CLAUDE.md`·`RUN.md` 가 그 시작) |

지금 가장 값이 큰 것은 **C** 로 본다 — 이미 쌓이는 데이터가 있고, 도면을 안 건드린다.

## 2. 지켜야 할 선 (연구라도)

| 선 | 이유 |
|---|---|
| **도면 내용은 나가지 않는다** | 문서명·뷰명·선택 수까지. 그 이상은 계약 위반 |
| 리빗 프로세스는 외부와 직접 통신하지 않는다 | 지금 구조의 전제. 깨면 보안 심사가 처음으로 돌아간다 |
| 쓰기(모델 변경)는 사람의 한 번 확인을 거친다 | 되돌릴 수 없는 작업이 섞인다 |
| 연구물은 `research\` 밖으로 나가지 않는다 | 졸업 조건 전까지 |
| 코어 규격을 고치지 않는다 | 고쳐야 한다면 그것이 곧 «졸업 심사 안건» 이다 |

## 3. 붙일 수 있는 자리 (이미 있는 것들)

연구는 **새 통로를 뚫지 않고** 기존 통로를 쓴다.

| 자리 | 지금 용도 | 연구에서 쓸 수 있는 것 |
|---|---|---|
| `runlog.jsonl` | 실행 기록 | C : 사용·사고 분석 |
| `memory.json` | 메모리·모듈 스냅샷 | C : «언제 재시작해야 하나» 판단 |
| `store.json` | 스토어 화면용 목록 | B : «이 도구 깔아 줘» |
| `cmd\` 요청 통로 | 화면 → 매니저 | B : AI 가 같은 통로로 시키기 |
| `BspAgent.Run()` | 실행 깔때기 | A/B : 무엇이 실행됐는지, 결과가 무엇인지 |

> 새 포트·새 서비스·새 권한을 요구하는 설계는 **일단 기각**한다.
> 파일과 기존 HTTP 두 갈래로 안 되는 것만 따로 논의한다.

## 4. 모르는 것 (조사할 목록)

1. MCP 서버를 어디에 둘 것인가 — 매니저 안 / 별도 프로세스 / 서버 쪽
2. 리빗 API 는 «리빗이 부를 때» 만 쓸 수 있다. 비동기 요청을 어떻게 태울 것인가
   (지금 답 : `ExternalEvent`. 큐 길이·시간 초과 정책 필요)
3. 모델 데이터를 어느 단위로 요약할 것인가 — 요소를 주지 말고 **판정**을 준다는 원칙의 구체화
4. 사내망에서 어떤 모델을 쓸 수 있나 (외부 API 금지 여부)
5. 감사 — AI 가 시킨 일과 사람이 시킨 일을 기록에서 구분하는 법
