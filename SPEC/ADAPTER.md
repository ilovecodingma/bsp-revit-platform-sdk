# 남의 서버를 런처 뒤에 붙이는 법

> 전제 : **서버는 우리 것이 아니다.** 이미 돌고 있는 남의 서버, 사내 파일 서버,
> 혹은 앞으로 그쪽이 만들 서버다. 런처는 그 서버에 맞춰 준다 — **반대가 아니다.**
>
> 런처가 서버에게 바라는 것은 딱 둘이다.
> **① 목록 한 장(JSON) ② 그 목록이 가리키는 파일.** 그 외에는 아무것도 요구하지 않는다.

---

## 세 가지 길 — 상황에 맞는 것 하나만 고른다

```
서버를 고칠 수 있나?
 ├─ 예 ─────────────▶ 길 A. 서버가 표준 목록을 직접 내려 준다      (가장 깔끔)
 └─ 아니오
     ├─ 파일은 올릴 수 있다 ─▶ 길 B. 목록을 만들어 같이 올린다     (가장 흔하다)
     └─ 응답 모양이 이미 다르다 ─▶ 길 C. 변환기를 하나 둔다        (기존 시스템 유지)
```

---

## 길 A — 서버가 표준 목록을 내려 준다

`AI\SERVER.md` 2장의 모양대로 `GET` 하나를 만든다. 필요한 필드는 여섯 개뿐이다.

```
id · latest · version · path · sha256 · url
```

주소·인증·호스팅은 전부 그쪽 자유. 런처 설정에 주소만 적는다.

```json
{ "manifestUrl": "https://update.회사.com/revit/catalog.json", "authHeader": "x-company-key", "token": "…" }
```

---

## 길 B — 파일만 올릴 수 있다 (가장 흔하다)

서버가 «파일을 올려 두는 곳» 이기만 하면 된다. 목록은 **우리가 만들어 같이 올린다.**

```powershell
.\AI\make-catalog.ps1 -Root .\배포할폴더 -Id myproduct -Version 1.0.0 `
                      -BaseUrl https://내서버/files -Out catalog.json
```

- 폴더를 훑어 **SHA-256 과 크기를 계산**하고 `catalog.json` 한 장을 만든다
- `-Merge .\catalog.json` 을 주면 기존 목록에 얹는다. **옛 버전은 남겨 둔다 → 되돌리기 수단**
- 만든 `catalog.json` 과 파일들을 서버에 올리고, `manifestUrl` 을 그 주소로 맞춘다

이 길은 **웹 서버조차 필요 없다.** 사내 공유 폴더면 충분하다.

```json
{ "manifestUrl": "file://\\\\파일서버\\bsp\\catalog.json" }
```

> 실측 : 파일만 있는 서버(파이썬 기본 http.server) + 이 생성기로
> **7/7 PASS** (설치 · 해시 · 변조 거부 · 새 버전 · 서버 정지 · 카탈로그 형식 · 실제 배포)

---

## 길 C — 이미 다른 모양의 응답을 주고 있다

기존 시스템을 고칠 수 없을 때. **런처를 고치지 않는다.** 사이에 변환기를 하나 둔다.

```
[기존 서버] ──그쪽 모양 JSON──▶ [변환기] ──표준 목록──▶ [런처]
```

변환기는 세 가지 중 편한 곳에 둔다.

| 두는 곳 | 어떻게 | 언제 |
|---|---|---|
| 서버 옆 | 엔드포인트 하나 추가 (`/revit/catalog.json`) | 서버에 코드를 얹을 수 있을 때 |
| 배포 담당 PC | 스케줄러로 주기 실행 → 결과를 공유 폴더에 | 서버를 아예 못 건드릴 때 |
| 올릴 때 한 번 | 배포 스크립트 끝에 `make-catalog.ps1` | 올리는 절차가 이미 있을 때 |

변환기가 하는 일은 하나다 — **그쪽 필드를 여섯 개 필드로 옮기는 것.**
`sha256` 이 원본에 없으면 **변환기가 파일을 읽어 계산해야 한다.** 이 값은 추측하면 안 된다.

---

## 어느 길이든 지켜야 하는 것

| | 규칙 | 안 지키면 |
|---|---|---|
| 1 | `sha256` 은 **실제 파일에서 계산한 값** | 런처가 배치를 거부한다 (그게 정상이다) |
| 2 | 같은 `(id, version, path)` 내용은 **영원히 고정** | 현장마다 다른 상태가 된다 |
| 3 | 고치려면 **새 버전**을 낸다 | 같은 버전은 런처가 다시 받지 않는다 |
| 4 | `latest` 는 `versions` 안에 있어야 한다 | «버전 없음» 으로 건너뛴다 |
| 5 | 옛 버전 항목을 지우지 않는다 | 되돌릴 방법이 없어진다 |

---

## 붙였는지 확인하는 법

```powershell
.\AI\selftest.ps1 -ManifestUrl "<그 주소>" -Token "<토큰>" -AuthHeader "<헤더 이름>"
```

7개 항목이 PASS 면 붙은 것이다. 흔한 FAIL 세 가지는 `AI\SETUP.md` 3장에 표로 있다.

> 이 문서의 요지 한 줄 :
> **서버가 무엇이든 «목록 한 장» 으로 번역만 되면 배포는 성립한다.**
