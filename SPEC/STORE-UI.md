# 스토어 화면 계약 — 화면은 그리기만, 판정은 매니저가

> 전제 : **화면은 이미 있다** (HTS 의 마켓스토어 UI 를 그대로 쓴다).
> 그래서 이 문서는 «어떻게 그릴지» 를 말하지 않는다. **무엇을 읽고 무엇을 시키는지**만 정한다.
>
> 원칙 하나 — **화면은 판단하지 않는다.** «받기인가 업데이트인가 차단인가» 는 매니저가 이미 정해서 준다.
> 그래야 화면을 바꿔도 규칙이 한 곳에 남는다.

---

## 1. 읽는 것 — `%AppData%\BSP\Platform\store.json`

동기화될 때마다 매니저가 덮어쓴다. 화면은 이 파일 하나만 읽으면 된다.

```json
{ "updated": "2026-09-22T07:53:34",
  "server": { "ok": true, "url": "https://…" },
  "revitYear": "2024",
  "products": [
    { "id": "p.one", "name": "첫째 도구", "publisher": "BSP", "kind": "tool",
      "minRevit": "2024", "latest": "1.0.0", "installed": "1.0.0",
      "action": "ok", "status": "설치됨", "files": 1 }
  ] }
```

### `action` — 버튼 하나를 이 값으로 정한다

| 값 | 버튼 | 뜻 |
|---|---|---|
| `install` | **받기** | 아직 없음 |
| `update` | **업데이트** | 새 버전 있음 (`installed` ≠ `latest`) |
| `pending` | (비활성) **다음 기동에 적용** | 이미 받아 뒀고 리빗을 껐다 켜면 적용 |
| `ok` | (비활성) 최신 | 할 일 없음 |
| `blocked` | (비활성) + `status` 그대로 표시 | 계약에 없음 · 꺼둠 · 배치 거부 |

`status` 는 사람이 읽는 문장이다 (`설치됨` · `꺼둠` · `배치 거부 — 해시 불일치 …`).
**화면이 문장을 지어내지 않는다.** 그대로 보여 준다.

### 서버가 죽어 있을 때

`server.ok = false` 면 목록은 **마지막으로 알던 상태**다. 화면은 «오프라인» 표시만 덧붙이고
버튼은 그대로 둔다. 눌러도 되고, 실패하면 아래 답이 온다.

---

## 2. 시키는 것 — 요청 파일 하나

에이전트를 참조하면 한 줄이다.

```csharp
var a = BspAgent.Install("p.one");     // 백그라운드 스레드에서
// a.Ok · a.Status · a.Pending · a.Message
```

에이전트를 못 쓰는 화면(다른 프로세스·스크립트)이라면 파일로도 된다.

```
요청  %AppData%\BSP\Platform\cmd\<티켓>.json      {"op":"install","id":"p.one"}
답    %AppData%\BSP\Platform\cmd\<티켓>.done.json {"ok":true,"status":"설치됨","msg":"첫째 도구 1.0.0"}
```

| `op` | 무엇 |
|---|---|
| `install` | 그 제품을 지금 받는다 (업데이트도 같은 명령) |
| `sync` | 목록 전체를 한 번 맞춘다 (새로 고침 버튼) |
| `enable` / `disable` | 그 제품 켜기/끄기 |

**실측 왕복 1.3초** (받기 + SHA-256 검증 + 배치 포함).

### 답을 화면에 옮기는 규칙

| 답 | 화면 |
|---|---|
| `ok=true`, `status="설치됨"` | 성공 표시 → 목록 새로 고침 |
| `ok=true`, `Pending=true` | **«리빗을 껐다 켜면 적용됩니다»** — 실패가 아니다 |
| `ok=false`, `status="배치 거부 — …"` | 그 문장 그대로. 다시 누를 수 있게 둔다 |
| `status="시간 초과"` | 매니저가 답이 없다 → «잠시 후 다시» + 상태 화면 안내 |

---

## 3. 진행 표시

받기는 보통 1~2초라 진행률 막대가 필요 없다. 오래 걸리는 경우(대용량·느린 회선)에는
`store.json` 의 `updated` 가 갱신되는 것으로 «살아 있음» 을 보이면 된다.
**퍼센트는 주지 않는다** — 부정확한 숫자보다 «받는 중 / 적용 대기» 두 상태가 정확하다.

---

## 4. 화면이 하면 안 되는 것

| 하면 안 되는 것 | 이유 |
|---|---|
| 자기가 파일을 받아 복사 | 해시 검증·잠김 처리를 건너뛰게 된다 |
| `action` 을 자기가 계산 | 규칙이 두 곳으로 갈린다 |
| «다음 기동에 적용» 을 실패로 표시 | 정상 동작이다. 사용자가 불안해한다 |
| 실패 문장을 바꿔 쓰기 | 원인 추적이 끊긴다 |
| UI 스레드에서 `Install()` | 리빗이 멈춘 것처럼 보인다 |

---

## 5. 화면 쪽에서 추가로 원할 만한 것 (있으면 말해 주면 넣는다)

| 요구 | 지금 | 넣는 법 |
|---|---|---|
| 아이콘·설명·스크린샷 | 없음 (`name`·`publisher` 만) | 카탈로그에 필드 추가 → `store.json` 에 그대로 흘림 |
| 분류·검색 태그 | 없음 | 같은 방식 |
| «이 회사 제품만» | 있음 (`allow` · 회원) | 서버가 카탈로그에서 걸러 준다 |
| 설치 이력 | `runlog.jsonl` 에 있음 | 화면용 요약이 필요하면 따로 내보낸다 |

필드를 늘리는 쪽은 **서버 → 카탈로그 → `store.json`** 순으로 흘리면 된다.
매니저는 모르는 필드를 지우지 않고 그대로 통과시킨다.
