# 사고 처리 — 막지 못하는 것을 «지목하고 끊는다»

> 밖에서 남의 코드가 리빗 안에서 하는 일을 막을 수는 없다. 무한 루프도, 메모리 폭식도,
> 네이티브 크래시도 못 막는다. **그래서 목표를 바꾼다 — 범인을 대고, 반복을 끊는다.**

---

## 1. 네 가지 사고와 각각의 답

| 사고 | 우리가 할 수 있는 것 | 못 하는 것 |
|---|---|---|
| **크래시** (리빗이 통째로 사라짐) | 실행 중이던 도구를 **지목**하고 셈한다 | 예방 |
| **멈춤** (응답 없음) | 지속 시간 + 그때 돌던 도구를 기록 | 그 도구만 골라 죽이기 |
| **메모리 폭식** | 단계·눈금으로 «언제 재시작할지» 를 숫자로 | 강제 GC · 언로드 |
| **로드 실패** (버전 충돌 등) | 못 실은 이유를 남기고 화면에 보임 | 남의 빌드를 고치기 |

---

## 2. 크래시 귀속 — `.running` 한 파일

```
도구 실행 직전 :  .running  ←  "<도구 이름>|<시작 시각>"
정상 종료     :  finally 에서 삭제
```

리빗이 사라졌는데 이 파일이 남아 있으면 **그 도구가 데리고 내려간 것**이다.
매니저가 다음 기회에 발견해 기록한다.

```json
{"t":"…","product":"bsp.launcher","tool":"crash.attributed",
 "outcome":"failed","running":"Export CAD","note":"Export CAD|2026-09-22T09:12:03"}
```

- `BspAgent.Run(제품, 도구, () => …)` 을 쓰면 이 표시가 **자동**으로 찍히고 지워진다
- 직접 쓸 때는 `finally` 에서 반드시 지운다. 안 지우면 멀쩡한 도구가 범인이 된다

---

## 3. 반복은 끊는다 — 3회 자동 격리

```
사고 1회  →  기록만
사고 2회  →  기록 + 경고
사고 3회  →  그 제품을 자동으로 끄고 (disabled) 화면에 이유를 남긴다
```

- 셈은 `crashes.json` 에 도구 이름별로 쌓인다
- 되살리는 것은 **사람**이 한다 : `bsp-launcher enable <제품id>`
- 격리는 «그 제품» 단위다. 도구 하나 때문에 제품 전체가 꺼지는 것이 과하다면
  카탈로그를 제품 단위로 잘게 쪼개면 된다 (규칙은 그대로)

> 자동 격리는 **판단이 아니라 브레이크**다. 원인은 사람이 본다.

---

## 4. 멈춤 감지

매니저가 60초마다 본다.

| 보는 것 | 기록 |
|---|---|
| `Responding == false` 지속 시간 | `memory.json` 의 `hangSeconds` |
| 그때 `.running` 에 있던 도구 | `running` |
| 메모리·핸들·스레드·모듈 수 | 같은 파일 (덮어쓰기) |

기록(`runlog`)에는 **변할 때만** 남긴다 — 단계 변화 / 500MB 눈금 / 모듈 25개 눈금 / 세션 종료.
매초 남기면 아무도 안 읽는다.

**죽이지 않는다.** 도면이 날아간다. 숫자를 남기고 사람에게 알린다.

---

## 5. 로드 실패

리빗이 애드인을 아예 안 싣는 경우가 있다. 가장 흔한 둘 :

| 증상 | 원인 | 확인 |
|---|---|---|
| 저널에 `Assembly version conflict` | 한 어셈블리에 같은 참조가 **두 버전** | `apply.ps1` 의 «참조 점검» 줄 |
| 탭은 뜨는데 누르면 죽음 | 선언 연도 ≠ 참조 `RevitAPI` 연도 | 같은 줄 |

둘 다 **배포 전에** 정적 검사에서 잡을 수 있다. 잡히면 게시하지 않는다.

---

## 6. 사고가 나도 지켜야 하는 것

| | |
|---|---|
| 도면 작업 | 절대 멈추지 않는다 |
| 기존 설치 | 실패해도 그대로 남는다 (받고·검증하고 그 다음 교체) |
| 기록 | 실패해도 로컬에 남는다 (전송 실패는 다음에 재시도) |
| 사용자 | «무엇이 · 어디서» 를 한 문장으로 본다. 스택 트레이스는 접어 둔다 |

---

## 7. 남는 한계 (숨기지 않는다)

- 도구 이름과 제품의 연결은 **이름 대조**다. 이름이 겹치면 엉뚱한 제품이 격리될 수 있다
  → 제품 id 를 도구가 직접 남기게 하면 정확해진다 (계약 v3 후보)
- 네이티브 크래시는 `.running` 이 안 지워진 채로만 잡힌다. 리빗이 정상 종료 경로로
  내려가면 표시가 지워져 «사고 없음» 으로 보인다
- 별도 AppDomain 격리는 **모델을 만지지 않는 도구에만** 가능하다
  (Revit API 객체는 도메인 경계를 못 넘는다 — `ElementId` 조차)
