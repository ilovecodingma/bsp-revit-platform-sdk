# 지시서 — 지금 있는 애드온(HTS)을 플랫폼에 태운다

> 이 파일을 AI 에게 그대로 주고 시작하면 된다.
> **기존 코드를 갈아엎지 않는다.** 껍데기만 바꿔 끼우는 작업이다.

---

## 0. 지금 구조 (측정된 사실)

| 것 | 실제 |
|---|---|
| 매니페스트 | `BSP.Hub.addin` **하나**. 도구마다 있는 게 아니다 |
| 등록 | `Registry.Load()` 가 `Tools\` 를 리플렉션으로 훑는다 |
| 실행 | `Registry.Run(int slot, UIApplication)` — **실행 깔때기가 이미 하나** |
| 계약 | `BSP.Contracts` (`IBspTool` / `IBspPanes` / `IBspGuide` / `ToolBus`) |
| 버튼 | `Slot000..119` · `Fav00..59` 를 미리 만들어 두고 매핑 |
| 도구 수 | 33개 (리빗 안에서 실제로 세어 `hts_manifest.json` 으로 구운 값) |

**좋은 소식** : 깔때기와 계약이 이미 있다. 플랫폼이 요구하는 모양과 8할이 같다.

## 1. 목표

HTS 를 **`kind: "bridged"` 제품**으로 만든다.

```
지금 : Revit ──BSP.Hub.addin──▶ BSP.Hub.dll (스스로 뜬다)
뒤 :   Revit ──플랫폼 .addin──▶ 플랫폼 ──첫 클릭 때──▶ BSP.Hub.dll
```

- HTS 의 `.addin` 은 **깔지 않는다** (런처가 `bridged` 면 자동으로 뺀다)
- 리본은 플랫폼이 만든다. HTS 탭은 사라지고 도구는 플랫폼 탭 안으로 들어온다
- `BSP.Hub.dll` 은 **처음 버튼을 누를 때** 로드된다 → 리빗 기동이 빨라진다

## 2. 순서

1. **도구 목록을 굽는다** — 리빗 안에서 `Registry.Tools` 를 한 번 읽어
   `%AppData%\BSP\Platform\hts_manifest.json` 으로 저장한다.
   *리빗 밖에서는 못 한다 — `RevitAPIUI` 는 혼합 모드라 로드되지 않는다. 시도하면 0개가 나온다*
2. **버튼을 만든다** — 구운 목록대로 플랫폼이 슬롯 버튼을 만들고, 클릭 시 `Registry.Run(slot)` 을 부른다
3. **깔때기를 하나로** — 모든 실행은 `Gate.Run` 을 지난다 (`.running` 쓰기 → 실행 → `finally` 로 기록·삭제)
4. **패키지로 만든다** — `BSP.Hub` 폴더 전체(15개 파일)를 그대로. `.addin` 만 뺀다
5. **검사** — `bsp-verify.exe <폴더> --id bsp.hts --version <버전> --target 2024`
6. **올린다** — `publish.ps1`

## 3. 반드시 걸릴 두 가지 (미리 안다)

### ① 참조 API 가 2021 이다
About 에는 «2024 전용» 이라고 적혀 있지만 실제 참조는 `21.0.0.0` 이다.
`BuiltInCategory` 가 2024 에서 32→64비트로 바뀌어, 그 배열을 쓰는 **정적 초기화가 클릭 순간 터진다**
(`RuntimeHelpers.InitializeArray` → `TypeInitializationException`). 탭·버튼은 멀쩡히 뜬다.

→ 2024 참조로 **다시 빌드**해야 한다. 라벨만 바꾸면 안 된다.
→ 다시 빌드할 수 없으면 그 도구는 카탈로그에서 2024 대상으로 **내리는 것이 맞다**.

### ② 서명이 없다
검사에서 `코드 서명 FAIL` 이 난다. 서명 없는 애드인은 리빗이 대화상자를 띄우고
**답할 때까지 멈춘다** (실측 1시간 45분). 인증서가 정해지기 전에는 사내 배포도 수동 확인이 필요하다.

## 4. 절대 하지 말 것

- HTS 의 `products.txt` 같은 **남의 설정 파일에 쓰지 않는다**
  *(실측 사고 : 런처가 이 파일을 썼더니 도구 33개가 전부 사라졌다. `Picked.Allows()` 가 그 파일을 읽는다)*
- 도구 소스를 «정리» 하지 않는다. 이번 작업은 로드 경로만 바꾸는 것이다
- HTS 가 쓰던 상태 파일 위치를 옮기지 않는다 (사용자 설정이 날아간다)

## 5. 합격 기준 (전부 리빗 안에서 확인한다)

| # | 항목 | 통과 조건 |
|---|---|---|
| 1 | 버튼 수 | 플랫폼 탭의 도구 수 == 구운 목록 수 (33) |
| 2 | 탭 | HTS 자기 탭이 **없다**. 플랫폼 탭 하나뿐 |
| 3 | 지연 로드 | 리빗 기동 직후 `BSP.Hub.dll` 이 모듈 목록에 **없다**. 첫 클릭 뒤에 **있다** |
| 4 | 실행 | 도구 3개를 눌러 전부 `runlog.jsonl` 에 `succeeded` 로 남는다 |
| 5 | 기동 시간 | 플랫폼이 기동에 더한 시간 < 200ms (`runlog` 의 `기동` 줄) |
| 6 | 무사고 | 세션 끝까지 `crash.attributed` 가 없다 |

3번이 이 작업의 핵심이다. 지연 로드가 안 되면 **바꾼 의미가 없다.**
