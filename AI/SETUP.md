# 자동 설치 지시서 — AI 가 물어보면서 맞춰 깐다

> **AI 에게** : 이 문서가 당신의 대본이다. 사용자는 리빗 애드인을 만드는 개발자이고,
> 자기 서버를 이미 갖고 있거나 곧 만들 사람이다. **한 번에 하나씩만 묻는다.**
> 모르는 답이 나오면 «기본값으로 두고 나중에 바꿀 수 있다» 고 알려 주고 넘어간다.
> 각 단계가 끝나면 **명령을 돌려 사실을 확인한 뒤** 다음으로 간다. 확인 없이 «됐습니다» 라고 하지 않는다.

---

## 0. 먼저 이것부터 (묻지 말고 실행)

```powershell
.\AI\healthcheck.ps1          # 이 PC 의 현재 상태
```

결과를 사용자에게 **그대로** 보여 준다. 여기서 이미 매니저가 돌고 있으면 «재설치» 가 되는 것이므로 그 사실을 말한다.

---

## 1. 질문 — 순서대로, 하나씩

### Q1. 업데이트를 내려 줄 곳이 이미 있습니까?

| 답 | 다음 |
|---|---|
| **있다 (HTTP 서버)** | Q2 로 |
| **있다 (공유 폴더만)** | Q2 로 — `file://\\서버\공유\catalog.json` 형식으로 받는다 |
| **아직 없다** | Q5 로 건너뛴다. 오프라인으로 깔고 나중에 주소만 바꾸면 된다 |

### Q2. 그 서버의 «목록(카탈로그)» 주소를 알려 주세요

- 예 : `https://update.회사.com/revit/catalog.json`
- 형식이 정해져 있지 않다면 `AI\SERVER.md` 2장의 모양을 쓰면 된다고 안내한다
- **이미 다른 모양의 응답을 주고 있다면** 그 응답 예시를 받아 온다 → Q3 으로

### Q3. (이미 다른 모양이라면) 지금 서버가 주는 응답을 한 번 보여 주세요

받은 응답을 보고 **둘 중 하나를 고른다.**

1. **서버를 조금 고칠 수 있다** → `AI\SERVER.md` 2장 형식으로 맞춰 달라고 안내.
   필요한 필드는 여섯 개뿐이다 : `id · latest · version · path · sha256 · url`
2. **서버는 파일만 올릴 수 있다** → `AI\make-catalog.ps1` 로 목록을 만들어 **같이 올린다.**
   ```powershell
   .\AI\make-catalog.ps1 -Root <배포할폴더> -Id <제품id> -Version <버전> -BaseUrl <파일 기준주소>
   ```
   웹 서버가 아예 없어도 된다 — 사내 공유 폴더면 `file://\서버\공유\catalog.json` 로 충분하다
3. **응답 모양을 바꿀 수 없다** → **변환기**를 만든다.
   그쪽 응답을 읽어 표준 카탈로그로 바꿔 주는 작은 스크립트를 짜고,
   그 결과를 파일이나 주소로 내보낸 뒤 런처의 `manifestUrl` 을 거기로 맞춘다.
   *런처는 절대 고치지 않는다. 맞추는 쪽은 언제나 서버/변환기다.* → 자세히는 `SPEC\ADAPTER.md`

### Q4. 인증이 필요합니까?

- 헤더 이름과 토큰을 묻는다 (기본 `x-bsp-key`)
- 토큰은 **화면에 다시 출력하지 않는다.** `config.json` 에만 쓴다

### Q5. 리빗 몇 버전을 쓰십니까?

- 기본 2024. 여러 개면 **주로 쓰는 것 하나**를 먼저 잡고 나머지는 나중에 추가한다
- 2025 이상이면 .NET 8 별도 빌드가 필요하다는 것을 알린다

### Q6. 지금 쓰는 애드인이 있습니까? (HTS 등)

- 있으면 이름과 위치를 받아 적는다. **이번 단계에서는 건드리지 않는다.**
  나중에 `AI\ADAPT_HTS.md` 로 옮긴다고만 말한다

## 2. 실행 — 답을 받은 대로

```powershell
.\AI\snapshot.ps1                                  # 되돌릴 수 있게 먼저 보관
.\AI\install.ps1 -ManifestUrl "<Q2 답>" -Token "<Q4 답>" -AuthHeader "<Q4 답>" -RevitYear "<Q5 답>"
```

- Q1 이 «아직 없다» 면 `-ManifestUrl` 없이 그냥 `.\AI\install.ps1`
- 이미 매니저가 돌고 있으면 종료 코드 3 이 난다 → 사용자에게 알리고 `-Force` 를 쓸지 **물어본다**

## 3. 확인 — 여기서부터가 진짜

```powershell
.\AI\healthcheck.ps1        # 매니저 1개 · 심장박동 60초 이내
.\AI\selftest.ps1           # 배포 사슬 5/5 (서버 없이도 돈다)
```

서버 주소를 받았다면 한 번 더 :

```powershell
.\AI\selftest.ps1 -ManifestUrl "<Q2 답>" -Token "<Q4 답>" -AuthHeader "<Q4 답>"
```

**결과표를 그대로 보여 준다.** FAIL 이 있으면 그 줄을 읽고 무엇이 문제인지 설명한다.
흔한 원인 세 가지 :

| FAIL | 원인 | 고치는 쪽 |
|---|---|---|
| 카탈로그 | `latest` 가 `versions` 에 없다 · `sha256` 이 64자가 아니다 | 서버 |
| 실제 배포 | 파일 주소가 404 · 인증 헤더 이름이 다르다 | 서버/설정 |
| 해시 | 올린 파일과 내려 준 파일이 다르다 (캐시·압축) | 서버 |

## 4. 리빗에 얹기 (원하면)

```
리빗을 닫은 상태에서 src\Entry\build.ps1 -Install 로 엔트리포인트를 설치할까요?
기존 애드인은 그대로 둡니다. [BSP] 탭과 [상태] 버튼 하나만 늘어납니다.
```

**반드시 묻고 진행한다.** 리빗 Addins 폴더를 건드리는 첫 단계이기 때문이다.
설치 후 확인은 `AI\TEST.md` 의 B-1 네 줄.

## 5. 마지막에 하는 말

- 지금 어디까지 됐는지 **표로** 정리한다 (매니저 · 배포 사슬 · 리빗 · 서버)
- 되돌리는 법을 한 줄로 알려 준다 : `리빗 닫고  .\AI\snapshot.ps1 -Restore`
- 다음에 할 일을 하나만 제안한다 (보통 `AI\ADAPT_HTS.md` 또는 `AI\SERVER.md`)

## AI 가 지켜야 할 것

1. **한 번에 하나씩 묻는다.** 질문 목록을 통째로 쏟지 않는다
2. **런처와 규격을 고치지 않는다.** 맞추는 쪽은 언제나 서버다
3. **확인 명령을 돌린 뒤에만** «됐다» 고 말한다. 출력을 그대로 보여 준다
4. 리빗 Addins 폴더·남의 제품 파일을 건드리기 전에는 **반드시 묻는다**
5. 토큰·비밀번호는 화면에 다시 쓰지 않는다
6. 실패한 것은 실패했다고 적는다. 부분 통과는 «부분 통과»
