# RUN — AI 가 혼자 끝내는 절차 (사람에게 되묻지 않는다)

> **이 문서를 읽은 AI 에게** : 사용자는 «붙여서 돌게 해 줘» 라고 했다.
> 계획을 설명하지 말고, 선택지를 늘어놓지 말고, **아래 순서를 그대로 실행**한다.
> 물어도 되는 것은 **딱 하나** — 업데이트 서버 주소. 그것도 모르면 오프라인으로 진행한다.
> 끝나면 **세 줄**로 보고한다. 로그 해설·경위 설명은 하지 않는다.

---

## 0. 규칙 (어기지 말 것)

1. **되묻지 않는다.** 아래 표에 답이 있다. 표에 없으면 기본값으로 가고 마지막에 한 줄로 알린다
2. **리빗을 마음대로 끄지 않는다.** 켜져 있으면 설치 단계만 건너뛴다 (나머지는 그대로 진행)
3. 실패하면 **1회 수선 → 재시도**. 그래도 안 되면 그 줄만 보고한다
4. 기존 코드·남의 제품 파일을 지우지 않는다. 되돌리기는 `snapshot.ps1 -Restore`
5. 검증 명령을 돌린 **뒤에만** «됐다» 고 말한다

## 1. 실행

```powershell
.\AI\wizard.ps1 -Auto                                   # 서버 주소를 모를 때
.\AI\wizard.ps1 -Auto -ManifestUrl <주소> -Token <토큰>   # 알 때
```

`-Auto` 는 묻지 않는다. 리빗 연도·애드인 프로젝트·설치 위치를 **스스로 찾아** 쓴다.
프로젝트가 여러 개 잡히면 첫 번째를 쓰되, 결과 보고에 한 줄로 적는다.

**프로젝트를 못 찾으면** 그때만 경로를 한 번 묻는다. 그 외에는 묻지 않는다.

## 2. 결과가 FAIL 이면 — 수선표대로 한 번 고치고 다시 돌린다

| FAIL 줄 | 원인 | 그 자리에서 할 일 |
|---|---|---|
| **참조 점검** : `... 가 2개 버전` | 계약/참조 DLL 이 옛 연도로 빌드됨 | 그 DLL 을 **대상 연도로 다시 빌드**한다. 어셈블리 버전은 **원본과 같게** 유지 (안 그러면 기존 도구가 바인딩 실패). 실례 : `BSP.Contracts` 21.0 → 2024 재빌드 |
| **참조 점검** : `RevitAPI 21.x — 선언 2024 와 불일치` | 라벨만 바꾼 빌드 | 그 프로젝트를 대상 연도 참조로 재빌드. 재빌드 못 하면 그 제품은 그 연도 대상에서 **뺀다** |
| **붙이기** : `OnStartup/OnShutdown 서명을 찾지 못함` | 진입점이 특이한 형태 | 그 파일을 열어 **두 줄만** 직접 넣는다 (`BspAgent.Attach` / `BspAgent.Detach`) |
| **빌드** 실패 | 참조 누락이 대부분 | 로그(`build.log`)의 첫 오류만 보고 고친다. 두 번 이상 헤매면 멈추고 그 오류를 보고 |
| **코어 검증** : `매니저 기동` FAIL | 매니저가 안 뜸 | `%AppData%\BSP\Platform\agent.err.log` 를 보고 고친다. 파일이 없으면 `bin\bsp-launcher.exe status` 를 한 번 돌려 본다 |
| **코어 검증** : `떼기` FAIL | 종료가 안 됨 | `config.json` 의 `exitGraceSeconds` 를 확인한다(기본 60). 시험 중이면 값을 줄여 다시 |
| **서버 연결** FAIL | 카탈로그 형식·주소·인증 | `SPEC\ADAPTER.md` 의 세 길 중 하나를 고른다. 파일만 호스팅하면 `make-catalog.ps1` 로 목록을 만들어 같이 올린다 |

수선은 **한 번**만 자동으로 한다. 같은 줄이 두 번 FAIL 이면 사람에게 넘긴다.

## 3. 리빗까지 확인 (리빗이 꺼져 있을 때만)

리빗이 켜져 있으면 **하지 않는다.** 꺼져 있으면 :

```powershell
.\AI\healthcheck.ps1        # 매니저 1개 · 세션 · 설치 목록
```

리빗을 직접 켜고 끄는 것은 사용자 몫이다. AI 가 임의로 리빗을 종료하지 않는다.

## 4. 보고 — 이 형식, 세 줄

```
적용 : <프로젝트 이름> · 리빗 <연도> · <OK n · FAIL m>
서버 : <주소 또는 «오프라인 — 주소만 채우면 연결»>
다음 : 리빗을 껐다 켜면 매니저가 자동으로 뜹니다 (되돌리기 : .\AI\snapshot.ps1 -Restore)
```

FAIL 이 남았으면 네 번째 줄에 **그 줄과 원인만** 적는다. 경위·시도 과정은 적지 않는다.

## 5. 사용자가 더 요구할 때만 하는 것

| 요구 | 할 일 |
|---|---|
| «업데이트도 붙여 줘» | 기존 «업데이트» 버튼 핸들러를 `BspAgent.Install("제품id")` 로 바꾼다 (`AI\ATTACH.md` 3장 2단계) |
| «켠 채로도 갈리게» | 도구 로드를 `BspAgent.Stage()` 복사본에서 하도록 바꾼다 (`SPEC\LAUNCHER.md` 2-2) |
| «서버를 만들어 줘» | `AI\SERVER.md` |
| «기존 HTS 를 올려 줘» | `AI\ADAPT_HTS.md` |

---

**요약** : `wizard.ps1 -Auto` 한 번 → FAIL 이면 표대로 한 번 고치고 재실행 → 세 줄 보고. 끝.
