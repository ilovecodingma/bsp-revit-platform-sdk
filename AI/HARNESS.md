# 하네스 — 우리는 최소만, 나머지는 직접 하시게

> 이 SDK 의 입장은 하나다.
> **우리가 만드는 것은 «가장 아래 한 겹» 뿐이고, 그 위는 대표님이 만드신다.**
> 대신 그 위를 만들 때 **혼자서 맞는지 틀린지 판정할 수 있는 도구**를 같이 드린다. 그게 하네스다.

---

## 1. 경계

| | 무엇 | 누가 | 형태 |
|---|---|---|---|
| **코어** | 붙이기·받기·검증·배치·수명·기록 | **우리** | `BSP.Platform.Agent.dll` + `bsp-launcher.exe` |
| **하네스** | 스스로 확인하는 도구 | **우리** | `bsp-probe.exe` · `selftest.ps1` · `healthcheck.ps1` · `make-catalog.ps1` · `snapshot.ps1` |
| **그 위** | 서버·화면·심사·요금·업무 도구 | **대표님** | 원하는 언어·틀·디자인 |

코어는 **리빗을 참조하지 않는다.** 그래서 어느 애드온에도, 어느 연도에도 들어간다.
화면도 없다. 화면은 이미 대표님 플랫폼에 있다.

---

## 2. 코어에 붙이는 데 필요한 줄 — 네 줄

```csharp
using BSP.Platform.Agent;

BspAgent.Attach("2024", pid);                 // OnStartup
BspAgent.Detach();                            // OnShutdown

var a = BspAgent.Install("제품id");            // 기존 «업데이트» 버튼이 부르던 자리
if (a.Pending) 사용자에게("리빗을 껐다 켜면 적용됩니다");

BspAgent.Run("제품", "도구명", () => 기존작업());  // 시간·성패·«누가 죽였나» 가 자동으로 남는다
```

그 외의 것(HTTP·해시·재시도·잠긴 파일·프로세스 수명)은 **밖에서 매니저가 한다.**
애드온 쪽 코드는 늘지 않는다.

---

## 3. 하네스 — 네 가지 질문에 각각 답하는 도구

| 질문 | 도구 | 판정 |
|---|---|---|
| «그냥 붙여서 돌게 해 줘» | `wizard.ps1` | 넷만 묻고 → 적용 → OK/FAIL 표 |
| «내 애드온에 붙기는 하나?» | `bsp-probe cycle <제품id>` | 7줄 PASS/FAIL. **리빗을 켜지 않는다** |
| «배포 사슬이 도나?» | `selftest.ps1` | 5줄 (설치·해시·변조거부·새버전·서버정지) |
| «내 서버가 규격에 맞나?» | `selftest.ps1 -ManifestUrl <주소>` | 위 5줄 + 카탈로그 형식 + 실제 배포 |
| «지금 이 PC 상태가 뭐지?» | `healthcheck.ps1` | 매니저·세션·설치 목록·기록·메모리 |

곁들이는 둘 :

- `make-catalog.ps1` — 파일만 올릴 수 있는 서버를 배포 서버로 만든다 (해시·크기 자동 계산)
- `snapshot.ps1` — 건드리기 전에 보관, 언제든 `-Restore`

### 하네스가 하는 일의 핵심

**사람의 눈을 판정에서 빼는 것.** «돌아가는 것 같다» 를 없애고
PASS/FAIL 과 종료 코드로 바꾼다. 그래야 대표님 쪽에서 우리 없이 진도를 뺄 수 있다.

---

## 4. 쓰는 순서 (대표님 쪽에서)

```
1) bsp-probe cycle              ← 리빗도, 서버도, 애드온 수정도 필요 없다. 코어만 확인
2) make-catalog.ps1 + selftest  ← 파일 하나를 실제로 배포해 본다 (서버 없이 file:// 도 가능)
3) 애드온에 네 줄 넣기           ← 여기서 처음으로 기존 코드를 건드린다
4) bsp-probe cycle <제품id>      ← 넣은 뒤 다시. 같은 표가 그대로 PASS 여야 한다
5) selftest -ManifestUrl <내 서버>← 서버까지 붙인다
6) healthcheck                  ← 현장 PC 에서 상태 확인
```

각 단계는 **앞 단계를 되돌리지 않고** 쌓인다. 실패하면 그 줄만 보면 된다.

---

## 5. 우리가 일부러 안 만든 것

| 안 만든 것 | 이유 |
|---|---|
| 서버 | 이미 갖고 계시다. 우리가 만들면 두 개가 된다 |
| 화면·스토어 UI | 이미 플랫폼에 있다. 코어는 `Install()` 만 제공한다 |
| 심사·요금·회원 정책 | 사업 판단이다. 코어는 «받은 파일이 올린 파일과 같은가» 까지만 본다 |
| 자동 업데이트(우리 자신) | 실패하면 복구 수단이 없다. 코어는 교체 대상에서 스스로를 뺀다 |
| 리빗 안 GUI | 애드온마다 다르다. 우리가 정하면 그게 제약이 된다 |

---

## 6. 판정 기준 (이 SDK 가 «됐다» 고 말하는 조건)

```
bsp-probe cycle <제품id>        7 PASS · 0 FAIL
selftest.ps1                    5 PASS · 0 FAIL
selftest.ps1 -ManifestUrl …     7 PASS · 0 FAIL   (서버를 붙였다면)
```

이 셋이 통과하면 «리빗 껐다 켜면 최신» 이 성립한다. 그 위는 대표님 영역이다.
