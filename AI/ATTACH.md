# 지시서 — 이미 있는 플랫폼 코드에 붙인다

> **AI 에게** : 사용자는 자기 리빗 플랫폼(애드인)을 이미 만들어 두었고, 그 PC 에는 리빗이 깔려 있다.
> 이 작업은 **새로 만드는 것이 아니라 끼우는 것**이다. 기존 코드를 갈아엎지 않는다.
> 넣는 줄은 네 줄이고, 기존 업데이트 기능은 **처음에는 그대로 둔다.**
>
> 각 단계 끝에 확인 명령이 있다. 확인 없이 «됐습니다» 라고 하지 않는다.

---

## 0-0. 자동으로 끝내려면

```powershell
.\AIpply.ps1 -Project <애드인 폴더/csproj> -ManifestUrl <서버 주소>
```

이 한 줄이 아래 1~4장을 그대로 수행하고 OK/FAIL 표로 끝난다.
**손으로 확인하며 가고 싶을 때만** 아래를 따른다.

## 0. 먼저 읽고, 먼저 물어본다

```powershell
.\bin\bsp-probe.exe cycle       # 코어가 이 PC 에서 도는지 (리빗·서버·코드 수정 없이)
```

7줄이 PASS 가 아니면 여기서 멈춘다. 붙이기 전에 코어부터 서야 한다.

그다음 **사용자 코드를 읽고** 다음 네 가지를 찾아 적는다. (추측하지 말고 파일·줄 번호로)

| 찾을 것 | 왜 |
|---|---|
| `IExternalApplication` 구현체의 `OnStartup` / `OnShutdown` | 붙이고 떼는 자리 |
| 지금 업데이트를 하는 코드 (다운로드·복사·버전 비교) | 나중에 위임할 자리 |
| 리빗 안 «업데이트/설치» 버튼 핸들러 | `Install()` 로 바꿀 자리 |
| 쓰는 리빗 연도 · 참조한 `RevitAPI` 버전 | 사고 예방 (아래 5장) |

찾은 내용을 표로 보여 주고 **어디에 넣을지 합의한 뒤** 코드를 고친다.

## 1. 참조 추가

```
BSP.Platform.Agent.dll   ← 프로젝트 참조에 추가 (Copy Local = true)
bsp-launcher.exe         ← 애드온 출력 폴더에 같이 놓는다 (애드온이 가장 먼저 찾는 자리)
```

- 이 DLL 은 **리빗을 참조하지 않는다.** 연도별로 나눌 필요가 없다
- net48(≤2024) 과 net8(2025~) 둘 다 같은 소스로 빌드된다 (`src\Agent\build.ps1 -Net8`)

## 2. 네 줄 — 이게 전부다

```csharp
using BSP.Platform.Agent;

public Result OnStartup(UIControlledApplication a)
{
    ...기존 코드...
    BspAgent.Attach(a.ControlledApplication.VersionNumber,
                    System.Diagnostics.Process.GetCurrentProcess().Id);   // ①
    return Result.Succeeded;
}

public Result OnShutdown(UIControlledApplication a)
{
    BspAgent.Detach();                                                     // ②
    return Result.Succeeded;
}
```

**주의** : `Attach` 는 예외를 던지지 않는다. 기존 `try/catch` 안에 넣어도 되고 밖에 둬도 된다.
오래 걸리는 작업이 아니지만, 확실히 하려면 백그라운드 스레드에서 불러도 된다.

### 기존 «업데이트» 버튼

```csharp
// 기존 : 직접 받아서 복사하던 코드
var a = BspAgent.Install("제품id");                                        // ③
사용자에게(a.Pending ? "리빗을 껐다 켜면 적용됩니다" : a.Status);
```

### 도구 실행 (선택 · 나중에 해도 된다)

```csharp
BspAgent.Run("제품id", "도구 이름", () => 기존작업());                      // ④
// 소요 시간 · 성패 · «리빗을 죽인 도구» 가 자동으로 남는다
```

## 3. 기존 업데이트 기능은 세 단계로 넘긴다

한 번에 걷어내지 않는다. 각 단계는 **되돌릴 수 있고, 그 자체로 쓸모가 있다.**

| 단계 | 하는 일 | 기존 코드 | 얻는 것 |
|---|---|---|---|
| 1 | `Attach`/`Detach` 만 | **그대로 둔다** | 누가 무엇을 언제 썼는지 · 멈춤·크래시 범인 · 메모리 기록 |
| 2 | 버튼이 `Install()` 을 부른다 | 남겨 두고 쓰지 않는다 | 해시 검증 · 잠긴 파일 큐 · 실패 시 기존 설치 유지 |
| 3 | 자동 갱신을 매니저에 맡긴다 | 지운다 | 리빗 껐다 켜면 최신 · 사용자 조작 0 |

**1단계만 해도 값이 나온다.** 위험은 사실상 0이다(기존 동작을 건드리지 않는다).

## 4. 실기 확인 — 리빗이 있으니 여기서 끝난다

```powershell
.\bin\bsp-probe.exe cycle <제품id>    # 넣기 전후 같은 표가 나와야 한다
.\AI\healthcheck.ps1                  # 매니저 1개 · 세션 · 기동 ms
```

리빗에서 직접 :

| # | 어떻게 | 통과 |
|---|---|---|
| 1 | 리빗을 켠다 | 기존 화면이 **전과 똑같다** · `healthcheck` 에 세션 1개 · 매니저 1개 |
| 2 | 기동 시간 | `runlog` 의 `attach` 줄이 수백 ms 이내 |
| 3 | 리빗을 닫는다 | 매니저가 **스스로 사라진다** (마무리 후 종료) |
| 4 | 리빗 두 개를 켠다 | 매니저는 **여전히 하나** |
| 5 | 리빗을 강제 종료한다 | 매니저가 세션을 걸러내고 종료 · 기록에 남는다 |
| 6 | (2단계 이후) 버튼으로 받기 | «설치됨» 또는 «다음 기동에 적용 N개» |

## 5. 미리 알고 가야 하는 사고 두 개

**① 선언 연도 ≠ 참조 연도**
About 에 «2024 전용» 이라 써 있어도 참조가 `RevitAPI 21.x` 면, 2024 에서
`BuiltInCategory` 가 64비트로 바뀐 탓에 **버튼을 누르는 순간** `TypeInitializationException` 으로 죽는다.
탭·버튼은 멀쩡히 뜨기 때문에 붙이는 작업과 헷갈리기 쉽다. 붙이기 전에 참조 버전을 확인한다.

**② 서명 없는 애드인**
리빗이 «보안» 대화상자를 띄우고 **답할 때까지 기동이 멈춘다**(실측 1시간 45분).
사내 무인 배포를 하려면 서명 정책을 먼저 정해야 한다. 이 SDK 가 대신해 줄 수 없는 유일한 항목이다.

## AI 가 지켜야 할 것

1. 사용자 코드를 **먼저 읽고**, 넣을 자리를 표로 보여 준 뒤 합의하고 고친다
2. 기존 업데이트 코드를 **지우지 않는다** (3장 3단계에 이르기 전까지)
3. 리빗 Addins 폴더·남의 제품 파일을 건드리기 전에 반드시 묻는다
4. 빌드가 되면 `bsp-probe cycle` 과 리빗 실기 6줄을 돌린 **결과를 그대로** 보여 준다
5. 실패한 것은 실패라고 적는다. 부분 통과는 «부분 통과»
